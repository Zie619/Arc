# ARC execution audit — 2026-09-05

The original product requirement is reconstructed in [purpose.md](purpose.md).
This audit focused on whether a long mission preserves its work, respects process
ownership, reports evidence honestly, and stops spending when it cannot proceed.
The starting revision was `1def747`; its baseline was 466 passing tests and a
clean typecheck.

## Changes

| Area | Reproduced or inspected problem | Result |
| --- | --- | --- |
| Competing resumes | Recovery changed live task state before claiming the arc | Claim before recovery; a refused contender changes no tasks or events |
| Lease lifecycle | Dry-run refusals and exceptions left leases active; delivery released ownership early | Hold ownership through delivery and release in `finally` |
| Lease race | Read then unconditional update admitted competing owners | Compare-and-swap over the inspected owner and expiry |
| Long synchronous work | An expired timestamp could make a live owner appear reclaimable | A live local owner is not stolen; owned task promises still occupy scheduler slots |
| Durable creation | An arc could be stored without all its task and criterion rows | Arc creation is one SQLite transaction |
| Checkout lock | Stale-file rename opened a gap for a third contender; malformed or foreign ownership could be misread | A short SQLite transaction serializes acquisition and release; malformed ownership refuses; foreign PIDs are not probed locally |
| Direct callers | Only the terminal UI acquired the checkout lock | `runDirect` owns the lock for every caller; UI preflight remains read-only |
| Read-only checks | A check could overwrite a sibling temporary worktree | Private scratch, denied outside writes and network; default refusal without an OS sandbox |
| Child environment | SSH-agent access was inherited; probes and contract compilers inherited the shell environment | Deliberate environments for those paths; explicit SSH grants only |
| Path identities | Sanitization could alias different identifiers or traverse a workspace path | Validate plan IDs; reject unsafe workspace IDs before provisioning or cleanup |
| Proof freshness | A criterion from an earlier attempt stayed checked after its proof failed | Invalidate prior criteria on a new implementation attempt; keep historical receipts |
| Combined result | A later task could invalidate an earlier task's command criterion | Run all configured gates and landed command criteria against the final integration tree |
| Review trust | A read-only reviewer could change its tree and still return a usable verdict | Snapshot review dispatches and reject mutated results |
| Integration verdict | A PASS label could coexist with retained major or critical findings | Blocking findings override the verdict label |
| Crash recovery | A task's original base differed from the integration head after a sibling landed | Reuse the persisted task base; retain partial commits |
| Landing receipt | Rebase and trailers changed the candidate commit after its recorded head | Record the exact candidate immediately before advancing the integration ref |
| Capability grants | Resume reloaded the old grant and kept a task quarantined | Re-probe current operator grants; retain frozen execution commands and completed task state |
| Scheduling | A slow task held up the next wave despite a free worker | Recompute the frontier as tasks settle, retaining dependency and collision checks |
| Blocking operations | The runner kept admitting work; no operator resolution command existed | Stop admissions, drain active work, record `arc.needs-input`; provide `arc ops` and receipted resolution |
| Capacity budget | Concurrent waiters could reserve the same remaining allowance | Reserve the wait before yielding, consistently with persisted wait events |
| Contract/footprint accounting | Findings were read through the wrong column; a contract scan was reused for a different base | Read `affects_json`, cache by base SHA, and reuse scheduler path normalization |
| Linux hang | Recursive mkdir under a nonexistent `/proc` path spun in Node 24 | Use one-level directory creation; ignore malformed remembered-choice data |
| Documentation | The README obscured the purpose and mixed guarantees between lanes | Shorter README; purpose, first-run, security, and generated configuration guides |

Tests were written to reproduce the principal failures before their fixes,
including live-owner mutation, leaked leases, temp-worktree writes, stale proof
acceptance, final integration regressions, idle worker slots, and ignored blockers.
The checkout lock test races six real processes. Other additions exercise the
operator CLI, read-only refusal on a simulated unsupported platform, and recovery
after a sibling advances integration.

## Remaining limits and next evidence to collect

- This remains an alpha for trusted local repositories. Worktrees share Git
  metadata; provider configuration, dependencies, and approved commands execute
  code with meaningful authority. See [security.md](security.md).
- The deterministic suite and benchmark use fake model providers. No paid model
  mission was run in this audit. A small real mission followed by an unattended
  multi-hour mission is still needed to measure model quality, quota behavior,
  and operational reliability with the new runner.
- The Claude agent process has no ARC-enforced OS sandbox. Linux read-only
  reproduction commands are skipped by default rather than given a containment
  guarantee ARC cannot provide.
- Capacity waits are durable budget reservations but still occupy a task slot.
  Parking a waiting task and rebuilding its continuation is separate work.
- Local PID reuse can conservatively refuse run ownership; distributed workers
  and network-hosted state are unsupported. Crash recovery also relies on the
  locally recorded provider process-group IDs.
- TypeScript contracts can be measured; other languages depend on declared
  contracts and executed validation. Review remains fallible.
- Direct edits have checkpoints and locking, not deep-run crash recovery.

No runtime dependencies were added. The supported Node minimum is now 24,
matching the Linux CI runtime and the documented first-run setup. Nothing in this
audit publishes a release or changes the user's unrelated repositories.
