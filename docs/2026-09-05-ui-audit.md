# Interface refresh — 2026-09-05

The interface now guides a user from a brief to an inspectable plan, a live
mission, and a concrete recovery action. The README has been rebuilt around that
experience, with a new SVG banner and a dashboard preview rendered from actual
components using example data.

## Changes

- A welcome screen explains ARC and exposes workflow, dashboard, help, and model
  selection. Shared colors and responsive dimensions connect the screens.
- `/lane` opens an arrow-driven workflow picker with each workflow's effect.
  Repository selection supports filtering; model selection keeps its selected
  row visible.
- The composer bounds large drafts around the cursor, wraps long lines without
  losing input, and scrolls command results to keep the selected item visible.
  Escape dismisses a command menu before interrupting work. Keyboard ownership
  is released when a panel closes.
- Plan approval supports task navigation and paged details: dependencies,
  footprints, gates, acceptance requirements, actual commands, and specifications.
  Delivery consequences and approval controls stay visible at ordinary sizes.
- `/dashboard` opens a read-only view in the conversation. Task lists and panes
  fit the terminal height, resize, and retain the selected run when another run
  appears. Tasks follow plan order and can be filtered for attention.
- Activity, Findings, Evidence, and Actions have separate panes. Evidence is
  compared against the required tier; waived requirements stay labeled.
  Long commands and receipts can be paged without truncating their content.
- `/digest`, `/why`, `/ops`, and `/resume` expose recovery without leaving the
  conversation. Operation resolution requires an explicit note. Thread-local
  inspection selects the thread's latest recorded run.
- `/queue clear` discards only queued follow-ups. Opening a dashboard does not
  cancel a mission. Follow-ups wait while a panel is open; switching threads
  during active work is refused with a useful explanation.
- CLI resume now honors `--id`, including supervised relaunches, even if a newer
  run or a local plan file exists. The standalone dashboard forwards run and
  repository selection and exits after a snapshot when output is redirected.
- `pnpm ui:preview` and `pnpm ui:preview --plan` exercise real components in a
  disposable store, without starting model providers. `pnpm docs:ui` regenerates
  the README dashboard asset.
